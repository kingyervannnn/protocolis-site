The first universal, self-healing, just-in-time web compiler for AI agents.

Browser agents have spent years teaching models to drive screens. That’s the wrong loop. Protocolis compiles the site instead, into a verified protocol. Typed actions, verified as they run. Learned verification adapts as evidence changes. A model-blind credential broker keeps secrets out of the agent’s context. No screenshot loop. No site-specific setup. No model inference in the compilation. Screenshot agents are the spinning disk; this is the solid state.

The trade the others make

Every other agent makes you shift gears yourself. Browser Use ships its own agent, a flash mode, a tools mode and a hosted Ultrafast; the faster the mode, the fewer tasks it finishes. So you pick a full mode for hard tasks and a fast one for easy ones, and pay for the wrong choice either way. Protocolis Adaptive is one mode that shifts on its own: step by step, the engine’s evidence decides whether a small choice model is enough or the agent’s model is needed. No fast mode, no full mode, and no trade. Measured against Browser Use, Browserbase’s Stagehand, Microsoft’s Playwright MCP and Jev Ultrafast on the same model and tasks.

Solid state, not a spinning disk.

A disk seeks before every read. A screenshot agent works the same way: look at the screen, think, act, look again, with a model call at every turn. Protocolis compiles the site instead. On first contact, with no model, no recording and no setup, it turns a site it has never seen into named operations your agent calls directly. Every call lands, and every answer is read from the page.

The screenshot loop

Hand the tool a task. Its own model looks at a screenshot, decides, acts and looks again, until it stops. You wait for the answer, and the model inside the tool is the one driving.

Solid state

Your agent keeps the wheel. The site is compiled into operations once, by rules alone; the agent calls them and reads the evidence. No model in the compiler, so a site the engine has never seen takes no model call to compile.

Documentation review · 5 November 2026 · Ratings use the definitions and scope below; they are not new benchmark results.

Comparison details & sources

Each alternative was reviewed individually against the same definitions. “Partial” includes narrower mechanisms and separately supplied cloud services. A dash means the reviewed sources do not establish the defined capability, not that support is impossible. Related technology does not earn partial credit when it fails an explicit cold or first-contact requirement. Protocolis ratings describe our engine’s supported capabilities; competitor ratings describe their published documentation and source, not independent runtime testing. Current documentation may differ from the versions used in the demonstrations and benchmarks.

A star marks a capability described in Protocolis’s pending US provisional patent applications. Pending applications are not issued patents.

What each row means
★ Just-in-time cold compiler engine
Cold means compilation on first contact with no site-specific adapter, prior training or recorded workflow. A compiler that requires recorded workflows does not meet this criterion.
★ Automatic transmission: one mode that shifts step by step
One mode decides at every step whether the compiled engine can carry it or full model reasoning is needed, on first contact, so the caller never chooses between a fast mode and a full mode. Automatic reuse of earlier cached or learned results receives partial credit.
★ Self-healing: verification that learns from outcomes
Verification learned from the engine’s own record of outcomes: checks that confirmed are promoted, checks the live evidence stops supporting are demoted or withdrawn, and each is re-checked against the live page before use. Model re-inference or retries after a failure receive partial credit.
★ Application operations compiled on first contact
Derives callable application-specific operations from the live application on first contact, without a site-specific adapter, taught workflow or prior recording. Recorded request-chain compilation does not meet this first-contact criterion.
★ Compilation without model calls
The compilation step itself requires no model inference; model-free replay alone is not enough.
Screenshot-free execution and result checks
Full support requires a documented first-contact workflow that both executes actions and checks the resulting page state without screenshots, while retaining its documented verification path. Text selectors or switching vision off alone are insufficient. This concerns outcomes observable in page data, not visual-only judgments. Agent-directed checks are distinguished from automatic verification in the separate verification rows.
★ Action effects verified on first contact
Checks action effects against live application evidence on first contact, without site-specific training or a previously recorded workflow. Agent-authored checks and generic assertions receive partial credit.
★ Task completion verified on first contact
Checks the requested task outcome against live application evidence on first contact, without site-specific training or a previously recorded workflow. A learned operation’s declared outcome does not establish this first-contact capability. Model judges and caller-supplied assertions receive partial credit for checking the task, with the limitations stated below.
★ Compiled knowledge reused across visits
Persisted application-derived operations are reused on later visits. Cached model-generated actions receive partial credit; manually authored scripts alone do not.
★ Verified replay with protected-action stops
Replay checks current application evidence and stops before protected actions. History reruns, retries or partial policy gates receive partial credit.
Built-in bot-protection handling
The product includes handling for bot-protected sites. A separately supplied cloud browser receives partial credit. No rating promises success against every protection.
Challenge handling and isolated escalation
Handles simple challenges and escalates difficult challenges in an isolated flow. Solving or waiting without the full escalation mechanism receives partial credit.
Challenge lessons shared across sites
Challenge-handling lessons transfer between sites; a site’s earlier history does not prematurely terminate a new attempt.
★ Credentials bound to verified fields
Secret values stay out of model context and are released only to verified fields on the current live page. Placeholders, masking or domain scoping alone receive partial credit.
★ New API keys captured model-blind
Newly generated API keys are captured into protected custody without passing through model-visible output. Redaction alone is not capture.
Passkeys
A built-in broker supports passkey registration and authentication for agent workflows, beyond reusing an already signed-in browser.

How we measured

Same model, same tasks, same budget. Every arm runs the same model on the same tasks, on live websites, arms rotating per task in one session. Protocolis Adaptive adds its small choice model, and its cost is counted.

Task sets. Short tasks: 20 public tasks, run in repeated rounds; each row gives its own run count. Long tasks: 40 long open-web tasks. Model sizes: 39 development tasks on live websites and component demos.

Completion. Short tasks are judged by checks on the finished page. Long tasks are judged blind by WebJudge from the screenshots, with a second judge on disputed tasks. Every attempt counts.

Time and cost. Time is a stopwatch from the task's arrival to the answer. Cost is the metered tokens at the provider's list prices, choice model included. Both are per completed task.
