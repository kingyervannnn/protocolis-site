Solid-State Web Execution: Compiling Web Applications into Verified Operations for AI Agents

Vahagn Boudakian · Protocolis

Read the paper Download PDF

PDF · 24 pages · 1.4 MB · version of 21 November 2026

A preprint. Posting to arXiv (cs.AI) is in progress; this page will link to the arXiv version once it is announced.

Abstract

Web agents have a language model read the page on every step, as a screenshot or as a structured snapshot, and decide what to do next. That per-step reading accounts for much of the time and cost of a web task and makes results depend heavily on which model is used. We evaluate a different design: a deterministic compiler that turns a page, on first contact and without any model call, into typed operations the agent invokes, each of which returns a verified result. To our knowledge it is the first such compiler in operation. We compare this system with widely used browser tools and browser agents, each as shipped, across three task lengths and three model tiers, judged by the same rules. It was the most stable system tested: across every task length and model size it never completed fewer than 55 percent of the tasks, while every other system fell to 28 percent or lower. On long tasks its better mode in each cell completed 80 percent (90 of 113), against 45 percent (51 of 113) for the best other system in each cell. A completed task cost 1.9 to 26 times less than with the cheapest other system on the same model. With its own agent it matched or exceeded the best other agent's completion rate in 9 of 9 cells, and as a tool in 8 of 9. It was the fastest system in 11 of 18 cells. On long tasks the judge rejected 22 percent of its reported finishes, against 56 percent for the other systems. Run on the small model, it cost less than every other system run on the frontier model in 30 of 30 pairings, and matched or exceeded its completion rate in 24. Every result is a first visit, with site memory and learning off and no site-specific code: the least favourable setting for the design, and the starting point for a deployment at volume. We report every cell in which another system leads and publish the tasks and the outcome of every run. The system is closed; access is provided for replication.
